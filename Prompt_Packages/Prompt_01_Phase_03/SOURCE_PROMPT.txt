## 8. Candidate selection and metrics

Choose one candidate separately for each E1–E4 experiment.

Selection rule:
1. Highest dev_tune macro-F1 over labels [0, 1].
2. If exactly tied, smaller C.
3. If still tied, class_weight=null before "balanced".

Do not use rounded displayed values for selection.

Use estimator-native hard predictions:
- Logistic Regression: estimator.predict
- LinearSVC: estimator.predict

Do not tune decision thresholds.

For every candidate, report:
- Macro-F1
- Positive-class precision, recall, and F1
- Accuracy
- Balanced accuracy
- Confusion matrix, explicitly ordered [0, 1]
- Class support
- Average precision from continuous positive-class scores
- ROC-AUC where defined

Call sklearn’s average_precision_score result “average precision.” Do not mislabel it as trapezoidal PR-AUC.

Use zero_division=0 for undefined precision/F1 and record when no positives are predicted.

Use:
- Logistic Regression positive-class probability for ranking metrics.
- LinearSVC decision_function margin for ranking metrics.

Verify the class order explicitly.
Never describe SVM margins as probabilities.
Do not apply a sigmoid and call the result calibrated confidence.

For Logistic Regression, native probabilities may be saved but must be described as uncalibrated.

With only 19 positives in dev_tune, differences may be unstable. These are development results used for selection, not final generalization estimates.

Do not select one overall project winner or drop an experiment because of these development results.
